# Manifests

The manifests directory contains the K8s manifest used to install the Cockroach
operator into a K8s cluster, as well as manifests for objects that the operator
itself creates and installs in the course of its work.

## Patterns

By convention, manifests are always exposed as Go functions in the `manifests`
package. These functions must directly or indirectly expose a slice of K8s
objects (`[]kube.Object`) that can be applied to a K8s cluster using the
`kube.Ctl` interface. The list of K8s objects are typically constructed in one
of two ways:

* By decoding K8s YAML config files from the `internal/yaml/` directory. The raw YAML
bytes are embedded in the Go binary as part of the build process by the
[`go:embed` directive](https://pkg.go.dev/embed).

* By writing custom Go code that constructs strongly-typed K8s objects, such as
`corev1.Pod` or `appsv1.Deployment`.

Often, creating the manifest requires custom parameters, such as the location of
an image or the number of replicas. In these cases, the manifest method takes a
list of options, which it then uses to parameterize a manifest template.

## Generated Files

The operator's YAML manifest is located at `manifests/internal/yaml/cockroach-operator.yaml`
and is generated as part of the build process from YAML fragments in the
`manifests/internal/yaml/operator/` directory. Note that the `crdb.*.yaml` files in that
directory are generated by the `controller-gen` tool from corresponding
`api/v1beta1/types/` files, and so should not be modified directly. By
contrast, the `yaml/operator/deploy.yaml` file, which governs deployment of the
operator's custom controllers, is maintained manually.
